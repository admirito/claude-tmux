#+TITLE: claude-tmux
#+OPTIONS: toc:nil num:nil

Shows in the tmux status bar which of your [[https://claude.com/claude-code][Claude Code]] sessions is working,
which is done, and which is waiting on you, and names each window after its
session instead of "claude".

#+begin_example
[0] 0:bash  1◓api-server  2◉docs-site  3◌infra-deploy  4◉refact…logic*
#+end_example

A window running Claude Code shows a mark in place of the colon, then the
session's name. Every other window looks exactly as it did.

| Mark                | Meaning                                                      |
|---------------------+--------------------------------------------------------------|
| =◐ ◓ ◑ ◒=           | working; the mark turns one step per status refresh          |
| =◌=                 | done, but a command it started in the background still runs  |
| =◉=                 | done; your move                                              |
| =◉= on darker green | waiting on you: a permission prompt or another dialog        |

A window with something you have not seen yet, an answer, a question or a
report that arrived since you last looked at it, is drawn in bold until you
visit it.

As a session's prompt cache runs out, the name turns navy with 30 minutes
left, blue with 20 and bright blue with 10; for the last 5 the window turns
light blue and its mark flashes to =❄=. Once the cache is cold the mark stays
=❄= until the session is used again, blue until you have seen it and black
after. A visit acknowledges the warning of the moment; the next one colours
the name again.

The name is the one given with =/rename=, otherwise the project directory's,
cut in the middle past 12 columns so both ends survive: =claude-statusline=
becomes =claude…sline=. tmux's own flags, =*= for the current window and =-=
for the last, stay at the end.

A session sent to the background from its window stays in that window's
cell, and the mark, the name and the cache follow it there.

To watch several sessions at once, open more terminals on the same tmux
session, each on a window of its own; see Mirrors below.

Almost none of this is mine. It was written by Claude, in Claude Code, across

* Requirements

- tmux 3.2 or newer. On anything older the loader changes nothing.
- =bash= 3.2 or newer and =jq=, with the usual =ps=, =awk=, =tail= and =date=.
- A Claude Code recent enough to record session status; seen from 2.1.215 on.
- Runs on Linux (tmux 3.2) and macOS (tmux 3.4 from Homebrew, the system's
  bash 3.2, BSD =ps= and =awk=).

* Install

#+begin_src sh
git clone https://github.com/admirito/claude-tmux ~/src/claude-tmux
#+end_src

Then add one line to =~/.tmux.conf=, after anything that sets =status-right= or
the window formats; with a theme loaded by tpm, that means after tpm's own
=run= line:

#+begin_src tmux
run-shell ~/src/claude-tmux/claude-tmux.tmux
#+end_src

and reload with =tmux source-file ~/.tmux.conf=. After a =git pull=, a change to
the script takes effect at the next refresh and a change to the look at the
next reload. To remove it, delete the line and restart tmux.

With [[https://github.com/tmux-plugins/tpm][tpm]], list it among your plugins instead of cloning it yourself,
after any theme:

#+begin_src tmux
set -g @plugin 'admirito/claude-tmux'
#+end_src

and press =prefix I= to install and load it; =prefix U= updates it. tpm loads
plugins in the order they are listed, and a theme loaded after claude-tmux
replaces its window formats, leaving the bar as if it were not installed. To
remove it, delete the line, press =prefix M-u= and restart tmux.

Changes appear within one =status-interval=, which also sets the pace of the
turning mark. tmux's default is 15 seconds and tmux-sensible sets 5;
claude-tmux leaves the setting as you have it.

* Configuration

Settings are tmux options, read when the loader runs. Set any of them before
the =run-shell= line; these are the defaults:

#+begin_src tmux
set -g @claude-tmux-width 12            # name width, cut in the middle; 0 for none
set -g @claude-tmux-busy '◐ ◓ ◑ ◒'      # several frames turn, one stays still
set -g @claude-tmux-busy-style ''
set -g @claude-tmux-shell '◌'
set -g @claude-tmux-shell-style ''
set -g @claude-tmux-idle '◉'
set -g @claude-tmux-idle-style ''
set -g @claude-tmux-waiting '◉'
set -g @claude-tmux-waiting-style 'bg=colour28'
set -g @claude-tmux-unseen-style 'fg=colour16,bold'   # '' to turn it off
set -g @claude-tmux-cache-left '30 20 10 5'           # '' to turn it off
set -g @claude-tmux-cache-styles 'fg=colour18 fg=colour19 fg=colour21'
set -g @claude-tmux-flash-style 'bg=colour117,fg=colour16'
set -g @claude-tmux-cold '❄'
#+end_src

The cache points are minutes left on a one-hour cache and scale with the
cache: on a five-minute one, 30 means two and a half minutes. Each point but
the last starts the next of the cache styles; the last starts the flash, drawn
in the flash style.

Styles are tmux styles. For bold black write =fg=colour16,bold=, as the unseen
default does: many terminals draw bold in plain black as grey.

** In your own format

Every window without Claude keeps your own window formats. To lay out the
Claude cell yourself as well, use these in your formats; a format that already
uses them is left alone.

| In a format          | Holds                                                    |
|----------------------+----------------------------------------------------------|
| =#{@claude_state}=   | =busy=, =shell=, =idle= or =waiting=; empty without Claude |
| =#{@claude_label}=   | the session's name, uncut                                |
| =#{@claude_unseen}=  | =1= when there is something you have not seen            |
| =#{@claude_cache}=   | the cache stage: =1=, =2=, ..., =flash=, =cold=; empty while warm |
| =#{E:@claude_mark}=  | the mark for the state, as configured                    |
| =#{E:@claude_name}=  | the name, cut to the configured width                    |
| =#{E:@claude_style}= | the style for the state, unseen and the flash, as configured |
| =#{E:@claude_cache_style}= | the name's colour for the cache stage, before the name |

* Mirrors

A mirror is one more terminal on your tmux session that moves on its own. All
of them show the same windows, each on a window of its choice, so one can
follow a Claude session while another watches a second. Two terminals
attached to one session would move together; a mirror is a session grouped
with yours, which shares the windows but not the current one, and goes when
its terminal does.

At tmux's prompt, =C-b := then =mirror=, a menu opens:

#+begin_example
┌──────────── Mirrors of main ────────────┐
│ New terminal mirroring this session (n) │
│ Make this terminal a mirror...      (t) │
├─────────────────────────────────────────┤
│ Close this mirror                   (c) │
│ Close all mirrors (2)               (a) │
└─────────────────────────────────────────┘
#+end_example

- *New terminal mirroring this session* opens another window of the terminal
  program you are in, starting on the window you are looking at.
- *Make this terminal a mirror...* picks a session, or a window of one, in
  tmux's chooser and moves this terminal onto a mirror of it. It suits a
  terminal just opened, whatever started tmux in it: the session the terminal
  leaves is removed when it holds nothing but an idle shell, and kept
  otherwise.
- *Close this mirror* closes this terminal's; *Close all mirrors* closes every
  mirror of the session, this one included. Each is greyed while there is
  nothing for it to close.

A mirror is named after the session it mirrors and the first free letter:
=0a=, =0b=, or =work-a= after a name that ends in a letter. =C-b $= renames
one.

Closing a mirror's terminal, or =C-b d= in it, closes the mirror as well, and
the windows stay. The terminal closes too when tmux was its command, and
returns to its shell when you started tmux by hand. Do not leave a mirror with
=exit= or =C-b &=: those close the window itself, which every mirror shares.

A new terminal is the same program as the one you asked from, found through
the processes above that terminal's tmux: xterm, st, urxvt, alacritty, kitty,
foot, konsole, ghostty, gnome-terminal, xfce4-terminal, terminator,
mate-terminal and wezterm on Linux, iTerm2 and Terminal on macOS. It opens
without the options the first one was started with. For any other terminal,
or to add options, give the command that runs a program in a new terminal:

#+begin_src tmux
set -g @claude-tmux-terminal 'xterm -fa Monospace -fs 11 -e'
#+end_src

Over ssh the new terminal would open on the other machine, so the menu says
so instead: open a terminal yourself, then choose *Make this terminal a
mirror*.

The settings and their defaults. The terminal is read each time a mirror
opens, the other two when the loader runs:

#+begin_src tmux
set -g @claude-tmux-mirror-command 'mirror'   # the command's name; '' for none
set -g @claude-tmux-mirror-key ''             # none; '+' for prefix +
set -g @claude-tmux-terminal ''               # '' to find it
#+end_src

The key is bound only when set, and never over a key bound to something else.
A command name you already use for a command of your own stays yours.

* What it reads, and what it writes

It reads the registry Claude Code keeps of its running sessions, one small file
each under =~/.claude/sessions= (or =$CLAUDE_CONFIG_DIR=), leaving alone the key
files beside them; the last 128 KB of each session's transcript, for when its
prompt cache was last used; the process table, to find the tmux pane each
session runs in; and tmux itself. The mirror menu reads the process table as
well, to find the terminal to open, and starts it when asked. It writes
nothing to disk and makes no network call.

Its changes are to tmux alone: it appends itself to =status-right=, wraps the
two window formats (keeping the originals in =@claude_orig_format= and
=@claude_orig_current_format=), and sets the options above plus a heartbeat,
=@claude_tick=, =@claude_seen=, when each window was last on screen, and
=@claude_cache_new= and =@claude_cache_left=, for the cache warnings. For
mirrors it adds the command to =command-alias=, binds the key when one is set
(remembered in =@claude_mirror_key=), and marks the sessions it creates with
=@claude_mirror=.

The registry is not a documented interface. Anything the script does not
recognise shows nothing, so a Claude Code release that changes it leaves your
usual bar rather than a wrong one.
